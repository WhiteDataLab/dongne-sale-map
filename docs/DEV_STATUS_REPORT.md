## 3. 6대 수익화 레버 — 현황 매트릭스

| 레버 | 무엇 | 구현 | 매출 ON 조건 |
|---|---|---|---|
| **L1 구독** | Free/Lite/Pro 정기결제(토스 빌링키) | ✅ 완료 | 토스 **실 계약·실키** |
| **L2 떨이 거래** | 픽업 예약·수수료(현장결제 v1) | ✅ 완료 | 수수료 청구 연결(빌링키) |
| **L3 성과형 광고** | 갈래요/길찾기 CPA | ✅ 완료(집행·집계) | 집행분 **수금 연결** |
| **L4 지역 광고** | 로컬 광고주 동네 타게팅 정액 | ✅ 완료(관리자 대행) | 광고주 **영업** + 셀프서브 콘솔(후속) |
| **L5 브랜드 리워드** | 기프티콘 후원 CPA | ✅ 완료(적립·리포트) | 브랜드 **BD** + 정산 송금 |
| **L6 데이터 B2B** | 비식별 물가 집계·리포트 | ✅ 완료(리포트·CSV) | **데이터 밀도** + 파트너 영업 |

**핵심**: 6개 레인이 *같은 트래픽* 위에 쌓여 있어, 구독 가맹점 수 하나에 매출이 갇히지 않습니다(브리프 적층 전략 그대로).

## 5. ⚠️ 사업기획 액션 아이템 (개발 영역 밖 = 매출 스위치)

> 아래는 **코드로 풀 수 없는** 항목입니다. 매출은 여기서 결정됩니다.

1. **🔴 토스 실 빌링 계약·심사** (P0) — 실키(`live_*`) 교체 전까지 모든 구독·수수료·CPA가 실제로 청구되지 않습니다. *가장 빠른 매출, 신규 개발 0.*
2. **🔴 첫 영업 스프린트** — `/admin/leads` CSV 100곳 → 무료체험 온보딩. 라이트(₩14,900) 임펄스 구간이 전환 훅.
3. **🟠 L4 광고주 영업 / L5 브랜드 BD** — 부동산·학원·병원(L4), 음료·FMCG 브랜드(L5)는 *영업 리소스*가 있어야 매출이 붙습니다(시스템은 준비됨).
4. **🟠 밀도(이문동 점령)** — L6 데이터 가치와 L4 광고 단가는 밀도에 비례. 한 동네 압도 후 클러스터 확장.
5. **🟡 사업자/약관 마감** — `/company` 사업자 정보, 전자상거래·환불 고지 점검(L2 결제 확장 전 필수).
6. **🟡 라이트 가격 A/B**(브리프 §13) — 정식 실험은 가격 변형 태그(소규모 추가 개발) 후 60~90일 관측.

## 7. 품질·검증 상태

- **빌드/린트**: 전 구간 `npm run build`·`npm run lint` 통과(경고 0).
- **E2E 검증**(세션 토큰 헤드리스): 티어 게이팅(402)·과금 누적/중복방지/자가클릭 제외·예산 소진·k-익명 suppress·신고 자동숨김 등 핵심 로직을 실제 API+DB로 확인하고 테스트 데이터 전량 정리.
- **데이터 모델**: 마이그레이션 **0~40** Supabase 적용 완료. (※ 배포 파이프라인은 마이그레이션 자동적용 안 함 → 신규 컬럼은 항상 `migrate deploy` 선적용 후 코드 push 원칙 유지.)
- **개인정보·보안**: GPS 미수집 원칙 유지(L4 타게팅도 *보이는 가게 주소* 기반), 단골/데이터는 **비식별·k-익명**, 사장님에게 손님 연락처 미노출.

## 8. 한눈에 보는 수익 공식 (브리프 재확인)

```
수억대 = 구독(L1 기본기) + 거래 수수료(L2 사용량) + 성과형(L3) + 지역 광고(L4 구매자풀 ×10)
        + 브랜드 리워드(L5 비용→수익) + 데이터 B2B(L6 고마진)
```

- **천장이 가장 높은 레버**: L2(거래)·L4(지역 광고). 둘 다 시스템 준비 완료 → 이제 *실행*의 영역.
- **가장 빠른 매출**: L1 구독 ON(토스 실 계약 1건) + 라이트 차별화 패키지로 전환율 견인.
